## 1. 项目目标与起源

用户希望在 ComfyUI 中把自己的 Codex/ChatGPT 订阅授权用于 GPT Image 生图，而不是在本地部署图像模型。ComfyUI 负责工作流编排和本地后处理，图像生成请求交给 CLIProxyAPI，再由 CLIProxyAPI 使用 Codex OAuth 路由到上游。

- 用户 fork：Fuck-GH-Admin/comfyui-gpt-image-bridge
- 插件原项目：Liu-Bot24/comfyui-gpt-image-bridge
- 早期社区候选曾包括 DocWorkBox/ComfyUI-Codex-ImageGen；用户认为旧节点更新停滞，决定直接 fork 可改造项目。
- 参考代理基座：router-for-me/CLIProxyAPI，当前已验证版本为 v8.0.57。
- 用户明确接受的产品思路：默认使用 Images API；有参考图时默认 Images Edit；Responses 保留为用户可选模式；不要强制把文本模型当作图像模型。
- 用户要求实际在 ComfyUI 环境运行，README 简洁说明使用，其他文档尽量详细。
- 用户反复强调：检查真实源码、利用 ComfyUI 官方节点能力，不要重复造轮子；测试要区分 mock、真实 ComfyUI、真实 Codex 上游；分支不应无意义膨胀。

## 2. 当前架构

请求链路：

    ComfyUI custom node
      -> CLIProxyAPI Provider（本地 OpenAI-compatible API）
      -> CLIProxyAPI v8 / Codex OAuth
      -> Codex 图片生成/编辑能力
      -> 图片响应字节
      -> 插件解码为 ComfyUI IMAGE Tensor
      -> ComfyUI 原生后处理 / SaveImage，或 PR #6 的本地编码节点

推荐 Provider：GPT Image Bridge · CLIProxyAPI Provider。  
本地 API base_url 示例：http://127.0.0.1:8317/v1  
CLIProxyAPI 客户端 Key 来自 config.yaml 的 access.api-keys。它不是 OpenAI API Key，也不是 Codex OAuth token。OAuth token 由 CLIProxyAPI 保存、刷新和使用。

Provider 还保留：
- 旧 Codex OAuth Provider：为兼容旧工作流保留；新部署不推荐作为主路径。
- 通用 API Provider：保留第三方 OpenAI-compatible API 和旧功能。

### 2.1 默认路由语义

- 纯文本 Generate：Images API /images/generations。
- Generate 接入参考图：默认 Images Edit /images/edits，第一张参考图作为 Image 1，属于“参考图引导式新图生成”，不是无参考图的 Generations 语义。
- Edit：Images Edit，支持基础图、附加参考图、可选 MASK。
- Responses：保留为可选路径，需要用户填写代理真实支持的 responses_model；不要假设某个文本模型在每个代理环境都存在。
- n 大于 1：CLIProxyAPI 路径通常按每张图发独立请求，可能分别消耗额度；不要把 n=4 说成一次请求。
- Generate 最多 16 张参考图；Edit 为 1 张基础图 + 最多 15 张附加参考图，顺序有意义。

### 2.2 主要控制项

- 模型名自由填写。当前真实账户已验证 gpt-image-2.6-flare、gpt-image-2.6-sunburst；历史旧型号 gpt-image-2 也有真实成功记录。模型权限因账户/地区/代理版本而异。
- quality：auto / low / medium / high / xhigh / max（旧型号可能不接受全部档位）。
- size：auto、常规尺寸、2K/4K 预设和 Custom。Custom 客户端检查：宽高 480–3840、16 的倍数、最大宽高比 3:1、像素总量 655,360–8,294,400。客户端接受参数不代表上游兑现。
- output_format：插件向上游请求 png/jpeg/webp；它与 ComfyUI 本地文件编码是两个概念。
- background：包含 transparent 等选项；只有响应真实带 Alpha，才能保留透明像素。
- moderation：PR #4 修复了 Images Generate JSON 与 Images Edit multipart 的 moderation 传递。
- image_complexity：当前插件控件仍有 low/medium/high，但 CLIProxyAPI v8.0.57 的 Codex Images 转换白名单不含 complexity，代理会丢弃。PR #9 修正了 tooltip 和文档。当前代理版本请保持 auto；不能把 UI 控件存在说成服务端生效。

## 7. 源码核对结论

### 7.1 Codex

OpenAI Codex 公开源码：
- image-generation tool: https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/tool.rs
- artifact saving: https://github.com/openai/codex/blob/main/codex-rs/ext/image-generation/src/artifact.rs

已核对：
- image tool 将透明背景选项映射为 ImageBackground::Transparent。
- Codex 保存返回图像时 Base64 解码后写原始 bytes，没有在保存路径强制 convert RGB。
- 该工具不是一个通用 JPEG/WebP 编码转换器；不能推断其支持任意 output_format。

### 7.2 CLIProxyAPI v8.0.57

源码：
https://github.com/router-for-me/CLIProxyAPI/blob/v8.0.57/internal/runtime/executor/codex_openai_images.go

已核对：
- Generate JSON allowlist: size, quality, background, output_format, moderation。
- Edit JSON allowlist: size, quality, background, output_format, input_fidelity, moderation。
- multipart Edit 使用同类 allowlist。
- complexity 不在 allowlist，因此 v8.0.57 会丢弃。
- CLIProxyAPI 将 Images API 请求转换为 Codex image_generation 路径；请求字段存在不代表模型执行/返回结果一定符合。

### 7.3 ComfyUI

源码基线：Comfy-Org/ComfyUI commit 63e5bf594339f676b4b15e072529873e3448409e（CI pinned ComfyUI 0.44.0 附近的源码基线）。

已核对：
- comfy_api_nodes/util/conversions.py 的 bytesio_to_image_tensor 默认在源图片含 Alpha band 或 palette transparency 时选 RGBA，否则 RGB。
- ComfyUI 的 SaveImage 用 PIL Image.fromarray 处理 IMAGE Tensor；四通道 Tensor 可保存 RGBA PNG。
- 本插件之前强制 RGB 是自身适配层 bug，不是 ComfyUI 核心限制。
- PR #5 已修复插件适配层；PR #6 进一步加本地格式编码节点。

## 8. 安装、运行和安全

### 8.1 当前 main 安装（六节点版本）

在 ComfyUI 实际 custom_nodes 目录：

    git clone --branch main --single-branch https://github.com/Fuck-GH-Admin/comfyui-gpt-image-bridge.git comfyui-gpt-image-bridge
    cd comfyui-gpt-image-bridge
    python -m pip install -r requirements.txt

必须用启动该 ComfyUI 实例的同一个 Python 环境安装依赖，然后完全重启后端。避免同时安装 Registry 上游版和本 fork，防止重复节点 ID。

### 8.2 CLIProxyAPI 最小本地配置

    config-version: 8
    server:
      host: "127.0.0.1"
      port: 8317
    access:
      api-keys:
        - "替换为随机客户端 Key"
    oauth:
      auth-dir: "~/.cli-proxy-api"
    multimedia:
      disable-image-generation: false

按 CLIProxyAPI 官方文档完成 Codex OAuth 登录，再启动服务。ComfyUI Provider 填：
- api_key：config.yaml 的 access.api-keys 客户端 Key
- base_url：http://127.0.0.1:8317/v1
- image_model：gpt-image-2.6-flare（若账户可用），或 gpt-image-2.6-sunburst
- reference_mode：images_edit
- responses_model：默认空，只有 Responses 模式才填
- image_complexity：当前 CLIProxyAPI v8.0.57 应保持 auto

首次真实请求建议 n=1、size=auto、quality=auto、background=auto、output_format=png。不要在未确认请求结果前重复提交。

### 8.3 安全约束

- CLIProxyAPI 初次只监听 127.0.0.1，不要为了方便把 API、管理面板或 OAuth 回调暴露公网。
- 工作流 JSON 可能保存客户端 Key 明文，即使 UI 中显示为掩码；分享前清空 Key。
- 不要提交 CLIProxyAPI config.yaml（若含 Key）、auth.json、OAuth token、浏览器 Cookie、Bearer Header。
- 不要将包含个人图片的 Base64、未脱敏日志或真实账户标识放入公开报告。
- 不要自动重试可能已经成功扣额度的图片请求；n>1 可能产生多次独立请求。
